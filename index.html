AI-Powered
Hospital Drug
Shortage

02 / 03

OpenEnv RL Environment

An end-to-end benchmarking environment for hospital medicine allocation, where agents make decisions under budget pressure, clinical safety constraints, uncertain demand, and supply-chain risk.

THE CHALLENGE

Allocate scarce medicines while balancing patient safety, partial information, and uncertain replenishment.

THE BENCHMARK

Six task families test scarcity progression, clinical overrides, forecasting, and perishable supply logistics.

OPENENV·REINFORCEMENT LEARNING·PYTHON·HF SPACES
Open Hugging Face Space ↗
Explore the benchmark design
01 / REINFORCEMENT LEARNING LOOP

Agents observe a simulated shortage state, choose an allocation action, and receive a reward before the next state.

  1. State
  2. Action
  3. Reward
  4. Next state
02 / TASK FAMILIES

Three core scarcity-progression tasks span easy, medium, and hard difficulty. Three orthogonal reasoning tasks add clinical override triage, forecast-based planning under partial observability, and perishable supply coordination.

03 / SYSTEM MODEL

The supply-chain task models shelf life, spoilage, cold-chain storage pressure, uncertain shipment reliability, and variable emergency-order lead times alongside budget and clinical constraints.

04 / EVALUATION

A standardized action interface, deterministic graders, and reproducible task distributions make agent behavior comparable as decision complexity rises.

Ablations disable substitutions, emergency procurement, or reserve planning to test how these capabilities affect decision quality.

05 / EVALUATION EVIDENCE

The repository documents reference grader scores from a deterministic run with seed 42. These are environment grader reference outputs, not trained-agent performance results.

Neural Predictive
Maintenance System

03 / 03

Multi-Sensor AI + Real-Time Inference

A multi-sensor system that models how industrial maintenance decisions move from continuous telemetry to calibrated, decision-oriented failure signals.

THE INPUT

Thermal, mechanical, and electrical events are buffered and fused into machine-level signals.

THE OUTPUT

FastAPI inference returns failure probabilities, risk bands, and signals for maintenance planning.

PYTHON·NEURAL MODEL·FASTAPI·STREAMING
Open live project ↗
Explore the inference system
01 / PREDICTIVE PIPELINE

The system turns continuous sensor input into risk and prediction signals.

  1. Sensor signals
  2. Data processing
  3. Model
  4. Inference
  5. Equipment health / prediction
02 / SIGNAL PIPELINE

Continuous thermal, mechanical, and electrical sensor events are buffered and fused before the neural model sees machine-level signals. A streaming simulation preserves temporal dependencies across machines.

03 / INFERENCE

The inference layer supports event-driven and aggregated inputs. The model output is translated into decision-oriented signals:

  1. Temporal Fusion CNN ↗
  2. Failure Probability
  3. Risk Band
  4. Maintenance Action
04 / EVALUATION METHOD

Threshold tuning, calibration analysis, and precision–recall trade-offs examine the different costs of missed failures and unnecessary maintenance.

05 / EVALUATION

ROC-AUC is the primary comparison. PR-AUC and recall are included as supporting measures. v2 results are from a simulated smart-factory stream, not real factory telemetry.
